# 工作模式

工作模式（Mode）决定 Agent 的**系统提示**与**可用工具范围**。通过 `/mode` 命令随时切换，无需重启。

## 切换方式

```bash
/mode            # 列出所有可用模式（内置 + 自定义）
/mode plan       # 切换到指定模式
/mode next       # 循环切换到下一个模式（等价于 REPL 内按 Tab）
```

也可在配置中设 `defaultMode` 指定启动模式。

## 内置模式

内置 8 种模式，分为「只读」与「全功能」两类：

| 模式 | 类别 | 说明 |
|------|------|------|
| `code` | 全功能（默认） | 自主读写文件、执行命令、完成任务 |
| `plan` | 只读 | 分析项目、输出实施计划，不修改任何文件 |
| `explain` | 只读 | 讲解代码结构与原理 |
| `review` | 只读 | 审查代码，输出问题清单与改进建议 |
| `debug` | 全功能 | 先复现 bug、定位根因、最小修复并验证 |
| `refactor` | 全功能 | 小步重构，保持行为不变并运行验证 |
| `test` | 全功能 | 编写与运行测试，优先补充覆盖 |
| `doc` | 全功能 | 编写与更新项目文档 |

### 只读模式的拦截机制

`plan` / `explain` / `review` 三个只读模式将可用工具限制为：

```
read_file / list_directory / glob / grep / stop
```

写工具（`write_file` / `edit_file`）与命令工具（`run_command` / `bash` / `powershell`）会被**自动隐藏并拦截**——即使模型尝试调用，也会被拒绝并提示当前为只读模式。这保证只读模式绝不会改动你的代码或执行命令。

### 各模式系统提示要点

- **plan / explain / review**：明确禁止修改文件与运行命令，仅用读/搜索工具，完成后以 `stop` 结束，输出结构化结果（计划 / 讲解 / 问题清单）。
- **debug**：要求先复现再修复，用读/grep/run_command 收集诊断，保持最小改动并诚实报告验证结果（含失败）。
- **refactor**：小步增量改动，每步后用 `run_command` 跑构建/测试验证，解释改动原因。
- **test**：先查看现有测试结构，针对需求补充聚焦测试，跑测试套件并诚实报告结果。
- **doc**：先读现有文档，保持风格一致，必要时更新文档索引。

## 自定义模式

在 `codeagent.json` 的 `modes` 列表中定义自己的模式，结构见 [配置参考.md](./配置参考.md#modes-子项agentmodeconfig)：

```jsonc
"modes": [
  {
    "name": "fix",
    "description": "修复模式：定位并修复 bug",
    "systemPrompt": "You are CodeAgent in FIX mode. Reproduce the bug, find the root cause, apply a minimal fix, then verify with the build/tests.",
    "tools": []          // 空数组 = 全部工具；填列表 = 仅限这些工具
  }
]
```

规则：

- `tools` 为空或省略时，该模式可使用**全部工具**；
- `tools` 填具体列表时，仅这些工具可用（可用于构造更严格的只读/专用模式）；
- 同名自定义模式与内置模式共存时，内置模式优先保留（自定义同名项不覆盖内置）；
- 自定义模式与内置模式一起出现在 `/mode` 列表中。

## ADOFAI mod 专属模式

当工作目录被识别为 ADOFAI（A Dance of Fire and Ice）mod 项目时，会自动注入 `moddev` / `harmony` / `assetbundle` 三个专属工作模式（同名自定义模式优先保留）。普通项目不受影响。
