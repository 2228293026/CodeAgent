# 开发指南

面向想构建、测试、发布或贡献 CodeAgent 的开发者。

## 环境要求

- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)
- 支持 Windows / Linux / macOS（命令执行在 Windows 上自动选用 Git Bash / PowerShell）

## 仓库结构

```
CodeAgent.slnx
├── src/CodeAgent/          # 主程序（控制台可执行，AssemblyName=codeagent）
│   ├── Program.cs          # CLI 入口：参数解析 + 交互式 REPL
│   ├── Config.cs           # 配置模型与加载（codeagent.json / 环境变量）
│   ├── Util.cs             # 通用工具（glob 转换、diff、编码探测、SkipDirs 等）
│   ├── GitInfo.cs          # 轻量 git 分支读取（解析 .git/HEAD，零进程派生）
│   ├── InputLine.cs        # 输入行：斜杠命令菜单 / 历史浏览 / 快捷键分发
│   ├── EditableLine.cs     # 可编辑文本缓冲（光标移动、词导航、代理对安全删除）
│   ├── HistoryStore.cs     # 命令历史持久化（.codeagent/history.txt）
│   ├── BracketedPaste.cs   # 括号粘贴标记探测状态机
│   ├── ConsoleRenderer.cs  # 模型回复 Markdown 终端渲染
│   ├── Modes.cs            # 内置工作模式目录
│   ├── SetupWizard.cs      # 交互式供应商配置向导
│   ├── AdofaiContext.cs    # ADOFAI mod 项目自动适配
│   ├── Providers/          # OpenAI 兼容 + Anthropic 双 Provider（含宽容 JSON/SSE 解析）
│   ├── Tools/              # 工具注册、文件/搜索/命令/会话工具、沙箱与撤销
│   └── Agent/
│       ├── Agent.cs        # Agent 主循环（裁剪/压缩、并行工具、取消）
│       └── Agent.Session.cs# 会话持久化（jsonl 日志、命名快照、导出、/find 搜索）
├── tests/CodeAgent.Tests/  # xUnit 测试（InternalsVisibleTo 访问 internal 成员）
├── docs/                   # 文档
├── publish.ps1             # 多平台发布脚本
└── .github/workflows/      # CI（build + test + release）
```

## 构建

```bash
dotnet build -c Release
```

项目为 `net10.0` 控制台程序，无第三方重框架依赖，仅用标准库 + 各 Provider 的 HTTP 调用。

## 测试

测试使用 xUnit，覆盖工具、配置、Provider 解析、Agent 循环、REPL 渲染等：

```bash
dotnet test -c Release
```

CI（`build.yml`）在 `ubuntu-latest` 上执行 `dotnet build -c Release` 后 `dotnet test -c Release --no-build`。

### 测试约定

- **命名**：`方法_场景_期望`（如 `GetInt_DoubleIntegralValue_Accepted`、`Load_UnknownTopLevelKey_ProducesWarning`）。
- **临时目录**：需要文件系统的测试用 `Path.GetTempPath() + Guid` 建目录，实现 `IDisposable` 在 `Dispose` 里删除（参考 `FileToolsTests` / `ConfigTests`）。
- **回归注释**：修复缺陷的测试在开头写 `// 回归：…曾…` 说明历史行为，防止回退。
- **不发真实网络请求**：Provider 测试用自定义 `HttpMessageHandler`（`CaptureHandler` / `SseHandler`）返回固定响应/SSE 流；Agent 测试用 `FakeProvider`。
- **纯函数优先**：解析/格式化/边界逻辑尽量抽成 internal 静态方法直接断言，不依赖控制台。

## 运行

```bash
# 交互式 REPL
dotnet run --project src/CodeAgent

# 一次性任务
dotnet run --project src/CodeAgent -- "把 Program.cs 里的 TODO 都实现掉"

# 交互式配置 / 生成示例配置
dotnet run --project src/CodeAgent -- --setup
dotnet run --project src/CodeAgent -- --init

# 列出当前 Provider 的可用模型
dotnet run --project src/CodeAgent -- --models
```

## 发布

`publish.ps1` 默认以「自包含 + 单文件」方式发布（对方无需安装 .NET 运行时），并把 `codeagent.example.json` 复制到输出目录：

```powershell
.\publish.ps1                                  # 发布 win-x64 到 dist/win-x64/
.\publish.ps1 -RuntimeIdentifier win-x64,linux-x64,osx-x64   # 一次多平台
.\publish.ps1 -SelfContained $false            # 依赖框架（体积小，对方需装 .NET 10）
```

也可直接用 `dotnet publish`：

```bash
dotnet publish src/CodeAgent -c Release -r win-x64 --self-contained false -o dist
```

分发时把对应平台的 `dist/<rid>/` 目录发给对方，对方复制 `codeagent.example.json` 为 `codeagent.json` 并填写 provider/model、设置 API Key 环境变量即可。

## 架构概览

```
用户输入 / 任务
      │
      ▼
Program.cs（参数解析 + REPL）
      │
      ▼
Agent 主循环（Agent/Agent.cs）
      ├─ 调用 Provider（OpenAI 兼容 / Anthropic）
      ├─ 解析模型返回的工具调用
      ├─ ToolRegistry 分发到具体工具（含工作区沙箱校验）
      ├─ 工具结果回填 → 继续推理
      └─ 直到模型调用 stop 或达到 maxToolIterations
```

- **Provider 抽象**：`IAgentProvider` 统一消息/工具调用中间表示；`OpenAiProvider` 走 chat completions + function calling，`AnthropicProvider` 走 messages + tool use；`ProviderFactory` 按配置创建。
- **工具层**：`ToolRegistry` 负责注册、分发与工作区沙箱；`FileTools`（read/write/edit/list）、`SearchTools`（glob/grep）、`CommandTool`（run_command/bash/powershell）、`SessionTools`（stop）。
- **配置层**：`Config.cs` 加载 `codeagent.json` / 全局配置 / 默认值，支持注释与尾随逗号。
- **模式层**：`Modes.cs` 提供内置模式 + 自定义模式，只读模式自动拦截写工具与命令。

## 贡献建议

- 新增工具：在 `Tools/` 下实现并在 `ToolRegistry` 注册，注意遵守工作区沙箱（`Workspace.Resolve` / `ResolveRead`）。
- 新增 Provider：实现 `IAgentProvider`，在 `ProviderFactory` 注册，并在 `codeagent.example.json` 补充示例。
- 新增模式：内置模式加到 `Modes.All`；用户自定义走配置 `modes`。
- 测试：在 `tests/CodeAgent.Tests/` 补充对应 xUnit 用例（测试程序集可访问 internal 成员）。
- 文档：用户向说明更新 `README.md`，开发者向说明更新 `docs/`。

## 提交与发布

- 每次提交前跑完整测试并通过（bash 下注意管道会吞退出码，用 `dotnet test 2>&1 | tail -1; test ${PIPESTATUS[0]} -eq 0 && git ...` 门禁）。
- CI：`ci.yml`（windows-latest，含 `dotnet format` 格式检查）与 `build.yml`（ubuntu-latest）都要保持绿色——后者专抓 Windows-only 假设。提交前本地先跑 `dotnet format --verify-no-changes`。
- 发布：推送 `v*` 标签触发 `.github/workflows/release.yml`，构建 win-x64 / linux-x64（依赖运行时）与 win-x64 自包含单文件（免装 .NET，约 47MB）产物并附加到 GitHub Release。版本号同步改 `CodeAgent.csproj` 的 `<Version>`。

## 文本编码约定（中文项目必读）

- **读文件一律用 `TextUtil.ReadTextSmart` / `ReadTextSmartAsync`**：BOM 优先，无 BOM 时严格校验 UTF-8，失败回退 GB18030（覆盖 GBK/ANSI）。禁止直接 `File.ReadAllText`——旧 Windows 项目的中文会变乱码。
- **写文件一律用 `TextUtil.WriteTextPreserveEncodingAsync`**：保持原编码（GBK 仍是 GBK、带 BOM 的 UTF-8 保 BOM），新建文件为无 BOM UTF-8。`WriteTextPreserveBom` 是仅保 BOM 的旧接口（撤销路径使用）。
- **命令输出**由 `ShellRunner.ReadWithCap` 读原始字节后走 `DecodeSmart`（中文 Windows 的 cmd/dotnet 输出 GBK 不乱码）；截断尾部用 `TrimPartialTail` 回退到多字节序列边界。
- **撤销**：`UndoEntry.EncodingName` 记录修改前编码（`DetectFileEncoding` 探测），恢复时按原编码写回。
- 会话日志/快照/配置序列化均使用 `UnsafeRelaxedJsonEscaping`（中文明文，可直接 grep）。
